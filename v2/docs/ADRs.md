# Decisions

* Backup options only STD or None.  CRR was removed as it would to
  know what is the replication region storage tariff.  (Not difficult
  for now, but if another region is added, it will become complicated).
  Also, this is only available for ECS at the moment (No SFS or Volume)
  Lastly, it is not clear how to configure CRR.
* Replicated storage (SDRS) was not implemented because it is not that
  commonly used.
* Pre-compute whenever we can, this to reduce the time spent
  calculating in Excel.
  * Price list - Backup Index
  * Volume Tiers Pricing
* Pipeline split to its own project.  Only fetches data.  This is
  really a work around the CORS restriction on the pricing API.
* Price Finder is a static sheet generated by the TS writer (no VBA),
  built on dynamic-array formulas (FILTER/SORT/SORTBY/UNIQUE/VSTACK)
  and data-validation dropdowns.  It works in every output (xlsx,
  xlsm, SPA) at zero runtime cost; requires Excel 2021/365 (accepted:
  the target environment is Microsoft 365).  The VBA alternatives
  (sheet built at open time, UserForm dialog) were rejected because
  they only exist in macro-enabled files.
  * The Finder's formulas are stored as legacy fixed-size CSE arrays
    (`t="array" ref` spanning the maximum output, padded with ""):
    the target Excel loads generated dynamic-array formulas as legacy
    (inserting `@` into plain `<f>` formulas).  Function names use the
    required OOXML spellings (`_xlfn._xlws.FILTER`/`SORT`, plain
    `_xlfn.SORTBY`/`UNIQUE`/`VSTACK`) — `_xlfn.SORTBY` because
    LibreOffice does not map the `_xlws.` spelling.
* Offline Trim with revival markers: the SPA's Trim is the TrimWB
  equivalent implemented in pure TS.  It freezes every formula
  referencing Prices to its cached result, records
  LiveRef/OriginalAddress/FormulaText in a veryHidden `_Frozen`
  sheet, and deletes the pricing/macro sheets; a later refresh can
  revive the frozen formulas.  Requires cached results (the file was
  saved by Excel).
* Pipeline-only staleness: the staleness check compares the
  T-recorded pricing source (schema, pricing-data date, params,
  patches) with fresh pipeline data, but excludes the `includes|*`
  keys — custom pricing is under user control and fairly static, so
  include drift (standard or custom) never flags a workbook stale.
  The check fetches only `prices-latest.json`, never the include
  CSVs.
* Refresh replaces only pipeline-owned sheets: Prices/Volumes/Finder
  (and T) are deleted and regenerated from the pipeline, while every
  user-owned sheet (BOM tabs, Overview, Assumptions, ESA) is left
  untouched.  BOM formulas resolve through `PriceList*` defined names
  rather than literal ranges, so pricing-schema changes flow through
  automatically.
* XLSM output merges the generated content into a macro host
  template (VBA project built separately with pyOpenVBA): the TS
  writer only ever produces xlsx content, so VBA changes never touch
  the writer.  The reverse conversion (`toXlsx`) strips macros by
  round-tripping content — ExcelJS never writes `vbaProject.bin`, so
  no zip surgery is needed.
* Edit includes? No, user edits off line (using a CSV editor) and adds it.
* Special Pricing:  can be added by uploading "csv" files in the
  customize UI.
